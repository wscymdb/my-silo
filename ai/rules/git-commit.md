# Git 提交规范与流程规则 (Git Commit Rules)

## 1. 任务完成后的提交询问
- **主动询问确认**：在每次代码、配置或文档修改/重构任务完成后，AI 必须主动询问用户是否需要协助进行 Git 代码提交（Commit）。
- **禁止自动 Push**：提交范围严格限定在本地 `git commit`，**严禁执行 `git push`** 操作，代码推送必须完全交由用户手动控制。

## 2. Commit Message 格式规范
Commit 信息必须严格遵循结构化规范，分为简要标题与精炼正文两部分：

```
<type>: <简要描述>

<详细描述>
```

### 规范细节：
1. **首行标题**：
   - 格式：`<type>: <简要描述>`（例如 `feat: 新增2D图像矩形标注插件`、`docs: 更新系统整体架构设计文档`、`fix: 修复多边形坐标变换计算错误`）。
   - 常用 Type 类型：`feat`（新功能）、`fix`（Bug修复）、`docs`（文档更新）、`refactor`（代码重构）、`style`（样式调整）、`test`（单元测试）、`chore`（工程配置/构建）。
2. **正文描述**：
   - 标题与正文之间**必须空一行**（回车换行）。
   - 正文列出本次提交的核心变更要点，语言简明精准，直击要害，**严禁冗长啰嗦**。

### 示例：
```
docs: 更新系统整体架构设计与技术栈选型

- 确立 Monorepo 工程结构与聚合主包发布策略
- 确定基于 Zustand + Immer 的轻量无头状态管理方案
- 明确内置 2D 图像与文本标注两大核心模态
```
